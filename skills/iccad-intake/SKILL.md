# 审查资料接收与报告基线

把「收到的一堆文件」变成「本轮可追溯的审查基线」。这一步做虚了，后面所有定位都不可靠。

## 输入与边界

报告正文、附表、图纸目录（或图纸）、计算书、专题报告、批复与审查意见、内审记录、委托书。

不判断内容质量，只建立：这是哪一版、包含什么、能支持哪一级核对、允许在哪里处理。

## 步骤

1. **列清单并取哈希**：对已授权目录运行 `inventory_inputs.py`，得到文件清单、字节哈希、格式能力与专业猜测。
   清单是**候选**，不是授权凭证，也不证明这就是受控版本。
2. **定基线**：确认送审批次（如「送审稿V2」）、基线日期、与上一版的差异范围。同名文件多版本时以**委托方确认的那份**为准，并在 `revision` 里写清来源。
3. **判能力**：每个来源写 `capability`。

   | capability | 含义 | 能支持什么 |
   |---|---|---|
   | `text_and_tables` | 可提取正文与表格 | 文字、数值、表格类核对 |
   | `text_or_scanned` | PDF，未知是否扫描件 | 先验证有文本层，否则降级 |
   | `scanned_image` | 无文本层 | 只能人工看图；相关检查记 `unsupported` |
   | `drawing_list_only` | 只有图纸目录 | 目录级一致性；**不能**核对图元 |
   | `tables` | 表格文件 | 工程量、单价、指标 |
   | `drawing_list_or_none` | DWG/DXF 无解析器 | 记 `unsupported`，不臆测图面 |

4. **记处理边界**：`processing.mode`、`environment_verified`、授权与脱敏记录号。声明不等于隔离，见[平台边界](../iccad-review/references/platform-adapter.md)。

## 通用核对项

| 项 | 核对什么 | 常见失败形态 |
|---|---|---|
| 责任表与签署 | 编制/校核/审查/批准人是否齐全、是否签署 | 只有姓名无签字；扫描页 |
| 设计资质 | 资质证号是否在有效期、是否与单位一致 | 附图承载，文本层取不到 |
| 签章 | 单位章、注册章 | 复印章、过期章 |
| 目录与页码 | 目录项与正文实际章节、页码是否对应 | 章节增删后目录未更新 |
| 附图附表 | 正文引用的图表是否都在 | 「见附图 X」但 X 不存在 |
| 工程等别与建筑物级别 | 全文是否一致 | 第 2 章 III 等、第 5 章按 IV 等取阈值 |
| 单位与量纲 | 是否统一（万 m³ / m³、m³/s / L/s） | 表格内外单位不同 |
| 版本标识 | 封面、页眉、修订记录是否一致 | 页眉 V1、封面 V2 |

> **判缺不等于真缺**：责任表、资质、印章常以图片或扫描页承载，文本层取不到。
> 记 `insufficient_input` 并注明「需打开源文档目视确认」，**不要直接判为缺漏**。

## 输出与交接

- `sources`：id、路径、哈希、修订、专业、能力、定位约定。
- 缺口清单：缺什么、应提供方、影响哪些检查项。
- 基线说明：本轮基线 ID、与上轮差异、以及**明确不在本次范围**的材料。

交接给 `$iccad-standards`（依据）与 `$iccad-route`（计划项）。缺关键篇章时不必中止全部审查，先做不受影响的部分，把缺口记清楚。
