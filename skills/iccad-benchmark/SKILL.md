# 审查试点回测与效果评估

回测的唯一目的是回答「这套东西到底帮上多少忙、帮错多少忙」。**用合成样本算准确率等于自欺**。

## 输入与边界

- 已授权的历史报告（脱敏）。
- **独立真值**：由未参与 AI 审查的人员整理的专家意见清单，含问题位置、性质、严重程度。
- 规则版本、模型版本、提示词版本与运行日期。

不做项目审查（那是 `$iccad-review` 的职责），只做效果评估。

## 指标

| 指标 | 定义 | 注意 |
|---|---|---|
| 检出率 | AI 意见与真值匹配条数 / 真值条数 | 按严重程度分层报告，合并平均没有意义 |
| 误报率 | 未被真值支持且人工复核确认为无效的条数 / AI 总条数 | 区分「错」与「真值未覆盖」 |
| 覆盖 | 已评估检查项 / 计划项；有真值但无对应计划项的比例 | 计划漏项是最隐蔽的失效 |
| 复核成本 | 单条 AI 意见的人工确认中位时长 | 决定实际可用性 |
| 稳定性 | 同一报告重复运行的条数与结论一致性 | 波动大则不可用于正式流程 |

## 匹配规则

- 位置 + 问题性质共同决定是否匹配；只对上一个不算。
- 「AI 提了同一处的另一个问题」记为误报 + 漏报各一，不记为命中。
- 严重程度错档记为部分命中，需在报告里单列。
- 真值本身存疑的条目，剔除并说明，不计入分母。

## 回测流程

1. 冻结规则与提示词版本，记录版本号。
2. 对每份样本运行，产出 `review.json`。
3. 盲评：先不看真值完成人工复核，避免被真值引导。
4. 匹配、统计、分层报告。
5. 对漏报逐条归因：计划漏项 / 依据缺失 / 能力不支持 / 模型判断偏差。
6. 对误报逐条归因：规则过宽 / 前提未校验 / 表述变体 / 引用错位。
7. 形成改动清单，改完**用同一批样本重跑**，确认召回未退化。

## 报告必须写清的边界

- 样本量、来源、时间段、覆盖的工程类型与阶段。
- 真值整理人的资历与独立性（不独立就不是真值）。
- 未覆盖的工程类型不推断结论。
- **不给「准确率 X%」这类单一数字**，按严重程度与专业分层给。
- 合成样本只能用于流程验证，不能用于准确率。

## 输出与交接

评估报告：指标表、分层结果、漏报与误报归因清单、改动建议与优先级、以及「本结果不外推到其他工程类型」的明确声明。

改动落地后，把新增的漏报补录为规则或检查项（`$iccad-rule-author`），把确认的误报登记为抑制条件——但**先登记再抑制**，不要直接删规则。
