# 洪评报告审查 — 规范取用与引用纪律

## 一、取条文的方法（唯一权威定义）

判词要有依据，依据要有条号，条号要能追到原文。取条文用 **`scripts/spec_lookup.py`**，
默认读**本技能自带**的 `references/flood_clauses.json`（16 部 / 6,439 块），
零外部依赖、与当前目录无关。

```bash
# 库内有哪些规范、各多少块
python scripts/spec_lookup.py --list-specs

# 查条文（关键词过滤）
python scripts/spec_lookup.py --spec "SL/T 808" --q 阻水比
python scripts/spec_lookup.py --spec "SL/T 808" --q 净空
python scripts/spec_lookup.py --spec "防洪标准"  --q 行洪区
# 多部一起查
python scripts/spec_lookup.py --spec "GB 50201,SL 252" --q 防洪标准

# 完全静默（诊断默认已走 stderr，stdout 只留条文正文）
python scripts/spec_lookup.py --spec "SL/T 808" --q 阻水比 --quiet
```

**查条文三条纪律**（不遵守会白跑一轮）

1. **用规范原文的术语，别用同义词。** `--q` 是**字面包含**匹配（已做**去空白 + 忽略大小写**
   容错 —— 库内正文多来自 PDF/OCR，常写成"阻 水 比"，直接查"阻水比"也能命中）。
   例：查 `坡式护岸` 在 GB 50707 里 0 命中 —— 那是 GB 50286 的词；换规范或换词。
2. **别带"表"字查条号。** 库内 `clause` 字段是 `7.2.4` 这种**纯数字**，`--q 表7.2.4` 会 0 命中。
   查条号直接 `--q 7.2.4`。
3. **优先用词组，别用单字。** 单字命中过多会白白塞满上下文（实测：查"坝"命中上百条、
   近万字符；查"坝顶超高"只有个位数条、不足千字符）。命中数看 stderr 的
   `matched: N (of M)`，N 过大就换更窄的词。

**限值表格**走 `flood_tables.md`（原文 docx 网格重建 + 条文库洁净文本双源互校）；
**强制性条文**走 `compulsory-clauses.md`。**三者都不可凭记忆写。**

**重建条文库**：规范库或收录范围变化后跑
`python scripts/build_clauses.py`（依赖本机块库 pkl 与 hydro_reviewer 源码树）。
日常审查**不需要**跑它。

## 四、引用纪律（7 条）

1. **条号必须取自原文。** 每条判定都要能追到"规范号 + 条号 + 原文"。取不到就标"依据待核"。
2. **区分"应/不应"与"宜/不宜"。** SL/T 808 用词：**必须/严禁** > **应/不应** > **宜/不宜** > **可**。
   "不应大于 5%"是**硬约束**；"宜采用下桩结构"是**推荐**。把"宜"当"应"判 = 误判。
3. **强条单独标注。** 触发 `compulsory-clauses.md` 里的条文 → 写"**违反强制性条文**"，最高级。
4. **两套判据别用混。** 挡墙抗滑：GB 50286 表 3.2.5 与 SL/T 386 表 3.4.5 **土基同值 1.35**，
   但**岩基不同**（GB 50286 1.15/1.10/1.08/1.05 vs SL/T 386 抗剪 1.10/1.08/1.08/1.05，
   SL/T 386 另有抗剪断 3.00/2.50/2.30）。按建筑物性质与所属规范选，**不可互代**。
5. **版本必须声明。** 引旧版 → 直接出"**引用已废止标准**"问题。要点：
   **SL/T 808-2025 替代 808-2021 与 SL 520-2014**；**SL/T 386-2025 替代 SL 386-2007 与 SL 379-2007**；
   SL/T 265（原 SL 265）、SL/T 191 等的新号前缀也须核。
6. **区分"防洪评价"与"洪水影响评价"。** 2021 年以前叫 **防洪评价**（SL/T 808-2021 原名
   《河道管理范围内防洪评价报告编制导则》）；**SL 520-2014** 叫《洪水影响评价报告编制导则》；
   2025 版合并为《洪水影响评价技术导则》。报告名/依据引旧名旧号 → 版本问题。
7. **库态只认实测。** 部数与块数用 `--list-specs` 点数，不用文件时间戳判断。

## 五、易踩的坑（10 条，实测所得）

1. **公式本体拿不到。** SL/T 808 的附录 A 公式在 docx 里是**嵌入图片**（36 张图 / 0 个 OMML）。
   块库只有**符号说明文字**。→ 复算时按"符号定义 + 水力学通用式"还原，**并标注待核**；
   正式成果以报告计算书为准。（`calc_backwater` 的 L_Y、`calc_scour --mode oblique` 均已如此标注。）
2. **块库 `table_text` 是否为空，随规范而异。** 部分规范（如 GB 50286）块内保留 markdown 表体；
   另一些（如 SL/T 386）全部为空。**不要假设**，限值一律以 `flood_tables.md` 固化值为准。
3. **OCR 空格会让关键词查不到关键条。** 库内 `5.2.2`（跨河阻水比 ≤5%）原文写作"阻 水 比"。
   本工具已做**去空白容错**修复 → `--q 阻水比` 现在能命中 `5.2.2`。
   但**同义词仍不通用**，只能换词或换规范。
4. **`--q` 不是语义检索。** 它是字面包含。查"桥墩"不会返回只写"支墩"的条；查"防洪标准"
   不会返回只写"设防标准"的条。→ 同一概念多试几个词。
5. **SL/T 808 的强条不在 2020 年版强条汇编里**（808-2025 晚于汇编）。洪评的法定强条落在
   **其引用规范**上 —— 最直接的是 **GB 50286 10.1.3**（与堤防交叉连接的建筑物应进行洪水影响评价）。
   不要把"库里没有 808 的强条"误读成"洪评没有强条约束"。
6. **"影响分析范围"最容易写小。** 表 1 是**上游及下游各段**的长度（山区 3B、丘陵 (3~5)B、
   平原 (5~10)B）。报告常只取"上下各 500m"而不核 B。且 **B 是两堤之间河宽**，
   无堤段用**历史最高洪水位河宽** —— 取值口径错了整章都错。
7. **"阻水比"要分三项。** 6.4.2 要求同时给**总阻水比、河槽阻水比、滩地阻水比** +
   占用行洪面积。只给总数 → 计算内容不完整。
8. **冲刷深度是三项叠加。** A.3.3 明确 = **演变冲刷 + 一般冲刷 + 局部冲刷**。
   报告只算局部冲刷就定"最大冲刷线" → 埋深判定失真。
9. **"净空"要分部位和工况。** 梁底 0.50 / 1.50 / 1.00 m 三档（按漂流物/泥石流），
   垫石顶面 0.25 m，拱脚 0.25 m —— 且**另有一列对照"最高流冰面"**。只对计算水位核、
   漏对流冰面核对，是常见漏项。
10. **蓄滞洪区项目有独立一套。** §5.5 与 §8 是**专门要求**（不减少蓄洪容积、避开进退洪口门、
    低路基、穿堤设挡水闸门、水上救生…），不能拿 §5.2~§5.4 的河道要求直接套。

## 六、本技能与同族技能的关系

洪评（本技能）与**河道工程**（`river-channel-report-review`）**判据有重叠但范围不同**：

| 维度 | 河道工程审查 | 洪评审查（本技能） |
|---|---|---|
| 对象 | 河道整治/堤防/护岸/清淤**工程本身的设计** | **建设项目对防洪的影响** + 洪水对项目的影响 |
| 主规范 | GB 50707 + GB 50286 | **SL/T 808-2025** |
| 关注点 | 断面/坡比/稳定/工程量 | 阻水比/壅水/冲刷/净空/埋深/蓄洪容积 |
| 报告名 | 可研/初设/施工图/安全评价 | **洪水影响评价报告**（原防洪评价报告） |

两者**都**要用 GB 50286（堤防稳定）、GB 50707（冲刷公式）。**判定口径须一致** ——
同一条款在两处取同一数值（本册 §十二 与 `rc_tables.md` §一/§二 已对齐）。
