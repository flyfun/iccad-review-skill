# 水运工程报告审查 — 规范取用与引用纪律

> **本册是引用纪律的唯一权威定义。** SKILL.md 与其余分册只写"查哪条"，不重复本册条文。

## 一、取条文的方法

```bash
# 1) 看库内有什么
python scripts/spec_lookup.py --list-specs

# 2) 按关键词查（默认全库；--spec 限定规范）
python scripts/spec_lookup.py --q 码头前沿设计水深 --limit 5
python scripts/spec_lookup.py --spec "JTS 167" --q 踢脚 --limit 3

# 3) 按条号查（纯数字！不要带"第""条"）
python scripts/spec_lookup.py --spec "JTS 167" --q 7.1.12 --limit 1

# 4) 查表（表号可带"表"字）
python scripts/spec_lookup.py --spec "JTS 144-1" --q 表10.2.5-1 --limit 1
```

`--quiet` 把诊断压到 stderr，stdout 只留条文，便于管道。条号**精确命中排最前**，其次前缀、包含、正文提及。

**本库的另一条路**：条文 JSON 就是 10 部规范原文的结构化结果，可直接用 Python 读
`references/pw_clauses.json` 的 `chunks` 数组，字段见 §二。

## 三、版本纪律（本域最容易出错的地方）

水运规范近年密集换版，**引用前先确认报告用的是不是现行版**：

| 现行 | 替代了 | 要点 |
|---|---|---|
| **JTS 165—2025** | JTS 165—2013 | 2026-02-01 施行。报告若仍引 165-2013，出"引用已废止标准" |
| **JTS/T 110-4—2025** | JTS 110-4—2008 | 报告编制规定同步换版，章节要求有变 |
| **JTS 167—2018** | JTS 167-1—2010（高桩）、167-2—2009（重力式）、167-3—2009（板桩）、167-4—2012（桩基）、JTJ 285/248/303/293/294 | **一部顶六部**；报告若仍按"高桩码头设计与施工规范"分册引，属旧体系 |
| **JTS 154—2018** | JTS 154-1—2011 | 名称由"防波堤设计与施工规范"改为"防波堤与护岸设计规范" |
| **JTS 181—2016** | JTJ 312—2003（航道整治）、JTJ 237—94（导标） | 航道整治不再用"整治工程技术规范"这个名 |
| **JTS 147—2017** | JTS 147-1—2010（港口工程地基）、147-2—2009（真空预压）等 | 桩基另分出去成 JTS 147-7 |
| **JTS 147-7—2022** | 原 JTS 167-4—2012 的桩基内容 | **桩基判据优先查这部**，与 JTS 167 第4章并行有效 |
| **JTS 145—2015（2022版）** | JTJ 145-1—2011（内河航运水文）、JTS 145-2—2013（海港水文） | 2022 局部修订（爬高/越浪），引用写"2015（2022年版）" |
| JTS 144-1—2010 | JTJ 215—98 | 现行（2024 局部修订附录 F） |

> **陷阱**：JTS 167—2018 的 7.2.11 正文里仍写"《防波堤设计与施工规范》(JTS 154—1)"——
> 这是**规范自身的旧引用**，不代表 JTS 154-1 仍现行。审查时不要把"规范原文写了旧号"
> 当成报告的错误，但报告若**自行**引用 JTS 154-1—2011 作判据，则应提示改用 JTS 154—2018。

## 四、引用纪律（硬规则）

1. **条号写全、写准**：`JTS 167—2018 第 7.1.12 条`，不写"7.1.12 节"、不写"7.1.12 条(1)款"混用。
   款级写 `第 3.1.2.1 款`。表写 `表 5.4.12-1`。
2. **水运用极限状态分项系数，不套水利的 K**：抗滑/抗倾没有"K≥1.1"这种判据。
   JTS 167 7.3.2 的形式是 `γ0(γE·EH + …) ≤ 抗力设计值`。凡报告只给"抗滑安全系数 K=1.25"
   而不给分项系数组合，本身就是**表达不合规**，应提示按 3.2.6 重算。
3. **强条只标到条/款，不标句**：JTS 规范公告多写"某条中的**黑体字部分**为强制性条文"，
   docx 转换后黑体标记已丢失（实测 `<w:b/>` 全部缺失），因此本库只能标到条级。
   引用时写"第 X 条（**强条**，黑体字部分）"，**不得**把整条都说成强制。
4. **不把编制规定当技术判据**：JTS/T 110-4—2025、JTS 120-3—2018 管"报告该写什么"，
   不判"数值够不够"。判数值要回到 JTS 165/167/154/181。
5. **同一事项多部规范都有规定时，取严**：如桩基承载力 JTS 167 第4章与 JTS 147-7 都管，
   两者不一致时按较严者，并注明两部条号。

## 五、最容易踩的 8 个坑

1. **把"码头前沿设计水深"当"航道设计水深"**：前者 JTS 165 5.4.12（Z1 只有 4 档底质），
   后者 6.4.5（Z1 按 6 档吨级 × 4 类土质），公式不同、富裕项不同。
2. **漏 Z4 备淤深度**：D0 是通航水深，D=D0+Z4 才是设计水深。有淤积港口 Z4 不宜小于 0.4m。
3. **Z2 不看船浪夹角**：表6.4.5-2 从 0°（0.24）到 90°（0.52）差一倍多；
   且 10000 吨级以下要 ×1.25。
4. **顶高程用错水位**：基本标准用**设计高水位**，复核标准用**极端高水位**，两套都要算；
   护岸还有"并应高于极端高水位"的硬约束（JTS 154 7.2.2.1 / 8.2.8.1）。
5. **堤顶高程系数张冠李戴**：斜坡堤允许越浪 0.6H、块石/四脚空心方块护面 0.7H、
   基本不越浪 1.0H；直立堤削角基本不越浪是 1.25H。护岸另有一套（0.8H/0.7H）。
6. **KD 用错**：块石抛填 2 层 4.0、安放 1 层 5.5、四脚锥体 8.5、四脚空心方块 14、
   扭工字/扭王字 15~18。拿 4.0 算扭王字块会把块体算重 3~4 倍。
7. **桩距不够却按单桩算**：表4.2.2 打入桩轴向 6d（或 3d~6d 且桩端进入良好持力层），
   低于门槛必须按群桩，否则承载力高估。
8. **把 JTS 144-1 第10章当强条**：该规范 12 条强条全在 5.1.1/5.2.1/5.2.2/6.1.1/7.0.x/
   8.0.x/11.0.6/12.0.2，**第10章船舶荷载一条强条都没有**。

## 六、库的结构与自检

`pw_clauses.json` → `{"meta", "specs", "chunks"}`；每条记录字段：

| 字段 | 含义 |
|---|---|
| `std_code` / `doc_name` / `source_spec` | 规范号 / 简称 / 版本全称 |
| `chapter` / `chapter_title` | 章号、章名（附录条记 `A`/`附录A`） |
| `section` / `section_title` | 节号、节名（无节标题时为空） |
| `clause` | **条号**（`7.1.12`）或**表号**（`表5.4.12-1`） |
| `level` | `clause` / `table` |
| `text` | 条文正文（款已并入，保留 `7.1.12.1` 款号） |
| `table_text` | 表格网格（`单元格 \| 单元格`，行间 `\n`） |
| `mandatory` / `mandatory_note` | 是否强条 + 说明（含"仅限某款"） |

**自检三问**（改库后必做）：

```bash
python scripts/build_clauses.py --list        # 条数/表数/强条数/乱序数
python scripts/spec_lookup.py --list-specs    # 每部块数是否与 §二 一致
```

① 强条数是否等于公告条数（167=46、165=12、145=18、144-1=12、154=6、181=15、147=3、147-7=4）；
② "乱序"是否接近 0（>5 说明章/节识别有问题）；
③ `mandatory_missing` 是否为空（有值说明公告条号在正文找不到，通常是款级合并或解析错位）。

**解析器的四道防污染措施**（改 `build_clauses.py` 时别拆掉，每条都是实测踩出来的）：

| 措施 | 防的是什么 |
|---|---|
| 正文起点只认首个 `1.0.1`，**不认"1 总则"** | JTS 167 制定说明尾部有编写人员清单 `1 总则：刘永绣`，形如章标题，会把正文起点提前并污染章名 |
| **章号一律由条号首段反推**（`7.1.12`→第 7 章） | 图注 `1-钢筋网3～5层`、年份行 `2018-03-12发布` 会被误判成章号 1/20 |
| 表号自带章号（`表5.4.8`→5） | 表记录若继承"当前章"，跨章排版时会张冠李戴 |
| `_clean` 合并**汉字-空格-汉字** | docx 段内换行被抽成空格，正文出现"造成经济损失 以及影响"，抄进意见难看；只合并汉字间，不碰 `50 m`、`1.30~1.40` |

另有两处已修的"断头记录"（条号被切掉、正文以 `.` 开头）：
① 父条标题段缺失时按父条号建档并保留完整款号（`5.4.12` 不再以 `.2 开敞式…` 开头）；
② 条号后多打一个句点（`C.0.1. 岩体结构类型…`）要剥掉。

## 七、换机器 / 换版本怎么重建

```bash
# 把新 docx 放进一个目录，改 build_clauses.py 顶部 DOCS 清单，然后：
python scripts/build_clauses.py --doc-dir "D:\规范\JTS" --out references/pw_clauses.json
```

`DOCS` 每项 `(规范号, 文件名, 简称, 版本全称, 是否主规范)`。**只依赖标准库**，
不需要源码树、不需要 pickle、不需要联网。
