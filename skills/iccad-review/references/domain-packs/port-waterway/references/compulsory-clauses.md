# 水运工程报告审查 — 强制性条文（强条）清单

> **强条 = 违反即写"违反强制性条文"，最高严重级 ★，不得降格为"不符规范推荐"。**

## 〇、五条纪律（先读，别跳）

1. **本册 116 条全部有出处**：逐部取自该规范**发布公告 / 制定说明**中的原文声明
   （"本《规范》第 X 条……中的黑体字部分为强制性条文，必须严格执行"），
   由 `build_clauses.py` 自动抓取并回填到 `pw_clauses.json` 的 `mandatory` 字段。
   **不是**从"含'应'字"猜的。
2. **只能标到条 / 款级，不能标到句级**。公告写的是"**黑体字部分**为强制性条文"，
   但 docx 转换后 `<w:b/>` 黑体标记全部丢失（实测 10 部无一保留）。
   因此本册给的是"**这一条里有强条**"，**不是**"这一条整条都是强条"。
   → 写意见时措辞用"**违反 JTS 167 第 7.1.12 条（强制性条文）**"，
   **不要**写"该条全文均为强制"；需要精确到句时，标"须核对原版黑体字范围"。
3. **两部没有强条，不等于不受约束**：`JTS 120-3-2018`（通航条件影响评价报告编制规定）
   与 `JTS/T 110-4-2025`（港口工程初步设计文件编制规定）是**编制规定**，
   公告未列强条。它们的条文是"报告该写什么"的**完整性判据**，缺项按 ● 判，不按 ★。
4. **"应"≠强条**。库里带 `mandatory=false` 的条文照样有"应/必须/不得"，
   那是**普通硬性要求**（● 级）。只有本册列出的条号才能写"违反强制性条文"。
5. **强条随版本走**。本册条号对应下表版本；报告引旧版规范时，先出"引用已废止标准"，
   再按**新版**条号判强条（旧版条号可能整体位移）。

**检索原文**（引用前必须核一次，别凭本册摘录下结论）：

```bash
python scripts/spec_lookup.py --spec "JTS 167" --q 7.1.12        # 单条
python scripts/spec_lookup.py --spec "JTS 165" --q 防火间距      # 关键词
python scripts/spec_lookup.py --mandatory-only --spec "JTS 167"  # 只看强条
```

## 二、JTS 167-2018 码头结构设计规范 —— 46 条

> 主规范。一句话记法：**"三个极限状态清单 + 四类码头各自的必算项 + 四道构造底线"**。
> 四道构造底线 = 变形缝（7.2.18 / 6.2.50 / 8.2.15 / 9.2.10 / 9.2.20）、
> 防腐（4.4.21 / 6.1.18 / 8.1.5）、倒滤（7.2.32）、栏杆（9.1.4）。

### 第 3 章 基本规定（2 条）

| 条号 | 强条内容 | 审查触发点 |
|---|---|---|
| **3.1.2** | 设计使用年限：永久性码头 **50 年**（3.1.2.1）；临时性可用临时年限或 **5~10 年**（3.1.2.2） | 报告写"设计使用年限 30 年/70 年"或未写 → ★。改扩建把旧码头沿用而不核剩余年限 → ● |
| **3.1.5** | 按失效后果严重程度划分**安全等级**，符合表 3.1.5 | 未定安全等级，或定了等级但 γ0 没跟着取（一级 1.1 / 二级 1.0 / 三级 0.9，表 3.2.2）→ ★ |

## 十二、四种最常见的误用（照抄会翻车）

1. **把"应"当强条**。JTS 167 全文 909 条里绝大多数含"应"，强条只有 46 条。
   写"违反强制性条文"前，必须先在本册查到条号。
2. **把"强条条号"当"整条强制"**。如 6.3.13 只是"锚碇叉桩计算"，同条内的
   构造要求不必然属强条。措辞用"第 X 条（强制性条文）"。
3. **拿旧版条号判新版**。JTS 167 由 6 部旧规范合并（高桩/重力式/板桩/桩基…），
   旧规范条号（如《港口工程桩基规范》JTJ 254）与新版**完全不对应**，
   照旧规范条号写 ★ 是硬错。
4. **漏"编制规定型"规范**。JTS 120-3 / JTS/T 110-4 没有强条，但报告缺章、
   缺专题、缺主尺度表，属**报告不合格**，应按 ● 提，且往往比单条 ★ 更影响通过。
