# 水资源论证报告审查 — 常见错情模式（30 条）

> 出发现前对照本册，**同类问题按模式归并、避免重复计数**，并据此定严重度。
> 每条 = **模式** + **典型表现** + **判定依据** + **默认严重度**。

**严重度**（本域无强条，故 ★ 的定义与族内不同）：
- **★ 命门级** —— 错了直接推翻"取水可行"的结论，或导致取水许可量错误；
- **● 不符规范 / 缺项** —— 明确违反某条"应"，或关键章节缺失；
- **○ 深度不足 / 前后不一致** —— 论证不到位、"宜"未满足、图文与数据不呼应。

> 判词写法：★/● 写"不符合 GB/T 35580-2017 第 X 条（原文要点）"；
> **任何一条都不得写成"违反强制性条文"**（见 `compulsory-clauses.md`）。

## 一、★ 命门级（13 条）

### ★1　水资源总量漏扣重复计算量
**典型表现**：`W总 = W地表 + W地下` 直接相加，不设"重复计算量"一行；
或设了行但数值为 0 / 空缺。
**为什么致命**：分母虚高 → 开发利用程度被低估 → 等级定低 → 全篇深度不足。
**判定依据**：水资源总量定义（地表 + 地下 − 重复）；7.2.2 要求给出水资源数量。
**抓法**：`calc_water_resources.py --mode total --report <报告总量>` ——
若报告值恰等于"直加值"，工具会直接点出"**漏扣重复计算量 X**"。

### ★2　取水量漏输水损失
**典型表现**：取水量只算到"用水环节"或"渠首"，输水损失另列但不并入；
或全篇没有"输水损失"三个字。
**为什么致命**：取水许可量偏小 → 实际取水超许可 → 违法风险。
**判定依据**：**3.9 取水量 = 新水量（包括输水损失）总和**；8.5.3 结合输水过程损失核定总用水量。

### ★3　水量平衡四量不闭合
**典型表现**：取 1200、用 1150、耗 700、退 400 —— 700+400=1100 ≠ 1150；
或退水系数全项目统一一个 0.8。
**为什么致命**：退水量错 → 退水影响、纳污核算、排污口规模全错。
**判定依据**：3.8 水量平衡；8.3.1 / 8.3.5。
**抓法**：`calc_water_balance.py --mode balance`（单系统）/ `--mode sum`（并联单元合计）。

### ★4　论证工作等级定低
**典型表现**：① 表1 地表水农业取水量把 `m³/s` 当 `万m³/d`；
② 钢铁/化工等高耗水重污染项目按表1 算出二级就定二级，**漏 5.2.2b 提级**；
③ 三类指标取平均而非取最高。
**为什么致命**：等级低一级 → 该做的数值模型、群孔抽水、丰平枯水质监测全部"合法"缺位。
**判定依据**：5.2.1（取最高级别）、5.2.2b（应提一级）、表1。
**抓法**：`calc_withdrawal_std.py --mode level ... --report <报告等级>`。

### ★5　开发利用程度的分母用错
**典型表现**：地下水开发利用程度 = 供水量 / **地下水资源量**（应为**可开采量**）；
或地表水用了"水资源总量"。
**为什么致命**：分母偏大 → 程度偏低 → 等级偏低 → 深度不足。
**判定依据**：**表1 注1**。
**抓法**：`calc_water_resources.py --mode exploit --kind 地下`。

### ★6　取水超区域用水总量控制指标
**典型表现**："项目取水 1200 万m³/a" 但区域总量指标 5200、现状已用 4300，余量仅 900，仍判可行。
**判定依据**：9.1.1（满足用水总量控制）、4.1 c)。
**抓法**：`calc_withdrawal_std.py --mode alloc`。

### ★7　入河量超水域纳污能力
**典型表现**：退水量 × 浓度算出入河量，但从不与纳污能力比较；或拿"达标排放"代替容量论证。
**判定依据**：11.2.3（符合水域纳污能力和限制排污总量控制方案）、11.2.5（未核定按 GB/T 25173 核算）。
**抓法**：`calc_withdrawal_std.py --mode retreat` → 把 kg/d 喂 `--mode capacity`。

### ★8　禁取区/禁取情形仍新增取水
**典型表现**：项目在**地下水超采区**仍新增工业取水；在**公共供水管网覆盖区**打自备井；
取用**深层承压水**而不论证必要性。
**判定依据**：**9.2.6**（三句，均为"不应/严格控制"）。
**抓法**：查报告是否附"管网覆盖图 + 供水公司接入意见 + 超采区划定文件"，缺一即无法排除。

### ★9　挤占河道内生态流量
**典型表现**：只算"取水量 ≤ 来水量"，不算取水后河道剩多少；或写"下泄生态流量 10%"却无依据。
**判定依据**：9.1.2（满足河道内最小流量或水量）、10.4.2（分析对生态流量与最小下泄流量的影响）。
**抓法**：`calc_demand_supply.py --mode eco --mean-flow X --withdrawal Y --eco-flow Z`。

### ★10　可供水量没做调节计算
**典型表现**：可供水量 = 多年平均径流 × 某系数，或"来水量 − 现状用水量"；
无调节性能的水源也这么算。
**为什么致命**：丰枯被抹平 → 枯水年保证率不成立。
**判定依据**：9.3.1.7（按调节性能选长系列/典型年，按时段做调节计算）、9.3.1.1（设计枯水径流）。

### ★11　定额与需水量不自洽
**典型表现**：定额 480 m³/亩 × 35 万亩 = 1.68 亿m³，报告年取水写 1.2 亿m³，不解释差额；
反推灌溉水利用系数 η = 1.40（>1，物理不可能）。
**判定依据**：8.2.7（按 GB/T 50363 分析灌溉制度）、8.5.3（核定总用水量）。
**抓法**：`calc_demand_supply.py --mode quota --kind 灌溉 --quota 480 --area 35 --eta 0.6 --report 1.2`。

### ★12　地下水资源量当可开采量用
**典型表现**：把"补给量 0.4 亿m³"直接写成"可开采量 0.4 亿m³"；
或给了可开采量但不扣**已有与规划用户**的开采量。
**判定依据**：9.4.1.2（水均衡算资源量）、9.4.1.5（扣已有与规划用户开采量后算可供本项目量）。

### ★13　有缺口却判"可行"
**典型表现**：远期缺口 0.15 亿m³，结论仍写"取水可行"，替代水源只在建议里一句"建议研究"。
**判定依据**：7.3.4（评价紧缺程度）、13.1（结论应明确可行性与条件）。
**抓法**：`calc_demand_supply.py --mode supply`；有缺口时看是否用 `--backup` 且落实到位。

| # | 模式 | 典型表现 | 判定依据 |

## 四、归并规则（避免同一问题重复计数）

1. **同一根因只报一次。** 如"总量漏扣重复量"会连带"开发利用程度偏低""等级偏低"——
   只报 ★1，把后两者写在**影响说明**里，不另立条目。
2. **数值错与文字错分开。** 数值不自洽 → 归 ★3/★11；文字未按条写 → 归 ●4/○5。
3. **同一指标在多个章节重复出现且都错** → 取**最严重**的一处定级，其余标"同前"。
4. **"宜"类不晋升级别。** ○1/○2/○3 只能停在 ○，不得因"影响较大"升为 ●。
5. **容量类问题一律 ★。** 超总量、超纳污、挤占生态水，三者任一成立即 ★，不因"超出不多"降级。
