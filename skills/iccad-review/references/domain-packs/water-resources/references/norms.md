# 水资源论证报告审查 — 规范取用与引用纪律

## 一、取条文的方法（唯一权威定义）

判词要有依据，依据要有条号，条号要能追到原文。取条文用 **`scripts/spec_lookup.py`**，
默认读**本技能自带**的 `references/wr_clauses.json`（GB/T 35580-2017 精编 **228 条**，
含表1 全文与表4 要点），零外部依赖、与当前目录无关。

```bash
# 库内有哪些规范、各多少块
python scripts/spec_lookup.py --list-specs

# 按条号查（**纯数字，不带"表""条"字**）
python scripts/spec_lookup.py --spec "GB/T 35580" --q 8.5.3

# 按关键词查
python scripts/spec_lookup.py --spec "GB/T 35580" --q 水量平衡

# 完全静默（诊断默认走 stderr，stdout 只留条文正文）
python scripts/spec_lookup.py --spec "GB/T 35580" --q 生态流量 --quiet
```

**查条文三条纪律**（不遵守会白跑一轮）

1. **用规范原文的术语，别用同义词。** `--q` 是**字面包含**匹配（已做**去空白 + 忽略大小写**
   容错），`--q 水资源论证范围` 能命中，`--q 论证边界` 命中不了。
2. **条号用纯号。** `clause/section/text` 三个字段都参与匹配，所以 `--q 9.4` 会命中
   §9.4 全节；带"表""条"字反而 0 命中。
3. **优先用词组，别用单字。** 命中数看 stderr 的 `matched: N (of M)`，N 过大就换更窄的词。

**限值表格**走 `wr_tables.md`；**数值速查**走 `numeric-checks.md`。**都不可凭记忆写。**

**重建条文库**：条文源文件增补后跑 `python scripts/build_clauses.py`。
本技能**不走块库**（见§二说明），日常审查不需要跑它。

## 四、引用纪律（硬规则）

1. **条号必须取自原文。** 每条判定都要能追到"规范号 + 条号 + 原文"。取不到就标"依据待核"。
2. **区分"应/不应"与"宜/不宜/可"。** 层级：**必须/严禁** > **应/不应** > **宜/不宜** > **可**。
   - "不应"= 硬约束（进 `bad`，rc=1）；"宜"= 推荐（只出 ▲ 提示）。
   - **实例**：7.3.2 统计资料"**宜**不少于 5 年" → 不足只提示，不判错；
     8.3.2 冷却水超 30% "**应**单独分析" → 缺即硬错。
3. **"应大于"≠"应不小于"。** 严格大于的条文（如 10.2.3 的"小于…10%"简化门槛）
   边界值不成立，别写成 ≥。
4. **本域无强制性条文。** GB/T 35580 是**推荐性**国家标准（GB/T），
   **不在《水利工程建设标准强制性条文》汇编内**。因此本技能所有判定最高到
   "不符合规范要求"，**不得写"违反强制性条文"**。这是与族内其他域最大的差别。
5. **两套判据别用混。** 水资源论证（GB/T 35580）与洪水影响评价（SL/T 808）、
   水保方案（GB 50433）各有各的账，同一"取水量"在三处的口径不同，**不可互代**。
6. **版本必须声明。** GB/T 35580-2017 现行；SL 322-2013 已废止。
7. **库态只认实测。** 块数用 `--list-specs` 点数（当前 228），不用文件时间戳判断。

## 五、易踩的坑

1. **表1 的地表水农业取水量单位是 m³/s，其余全是 万m³/d。** 这一处单位错位会让等级差 2 级，
   是全表最容易被整列套错的地方（`calc_withdrawal_std.py --mode level` 已内置提示）。
2. **"开发利用程度"的两个分母不同。** 地表水除以**地表水资源量**，地下水除以**地下水可开采量**
   （表1 注1）。除以"水资源总量"是错的。
3. **GB/T 35580 没有"重复计算量"条。** 扣重公式来自水资源总量定义（SL/T 238 / 水资源公报口径）。
   写判词时说"按水资源总量定义"，别说"按 GB/T 35580 第 X 条"。
4. **10.2.3 的简化门槛是双条件"或"关系**：累积取水量 < 历年实测最小流量的 **10%**，
   **或** < 多年平均最枯月流量的 **5%**。满足任一即可简化，别当成两个都要满足。
5. **生态流量没有全国统一百分比。** 10.4.2 只要求"分析对生态流量（水位）的影响"，
   没给 10%/30% 这类数。本技能 `--mode eco` 里的 Tennant 10%/30% 是**量级参考线**，
   不是规范限值 —— 判词里不得写成"按规范应达 10%"。
6. **纳污能力零维式只适用于充分混合的小型河段。** 大江大河与一级论证须用报告自身的模型，
   本工具只作量级校核（`capacity` 模式已在输出中声明）。
7. **"取水量"含输水损失（3.9）。** 报告常把取水量只算到用水环节，导致取水许可量偏小。
8. **退水量不含水轮机排水（3.10）。** 水电项目套用一般工业的退水系数会算错。
9. **条文库是精编，不是全本。** 表2/3/5/6 未收录，涉及时查正文。别因为"库里没有"就说"规范没要求"。

## 六、与同族技能的关系

| 报告类型 | 走哪部技能 | 主规范 | 与本域的重叠点 |
|---|---|---|---|
| **建设项目水资源论证** | **本技能** | **GB/T 35580-2017** | — |
| 洪水影响评价 / 防洪评价 | `flood-impact-report-review` | SL/T 808-2025 | 都涉及"取水/退水对水功能区影响"，但洪评重在阻水与河势 |
| 水闸工程 | `sluice-report-review` | SL 265-2016 | 水闸取水口布置、闸下水位；**不管**水资源配置与总量 |
| 泵站工程 | `pump-station-report-review` | GB 50265-2022 | 泵站取水水源可靠性；**不管**论证等级与三条红线 |
| 河道整治 / 堤防 | `river-channel-report-review` | GB 50707 / GB 50286 | 河道内取水口布置与河势；**不管**用水定额与退水纳污 |
| 土石坝 | `earth-dam-report-review` | SL 274 | 水库作为取水水源时的调节计算（SL 104） |
| 水土保持方案 | `soil-conservation-report-review` | GB 50433 / GB 51018 | 施工期用水与弃渣；**不管**取水许可 |

**分工口径**：只要报告的核心命题是"**这个项目能不能取这么多水、取了之后对别人和生态有没有影响**"，
就归本域；若核心命题是"这个建筑物本身安不安全"，归对应建筑物域。
一份报告同时含两部分时，按**主命题**选技能，另一部分只做一致性交叉核对（不重开全套 12 块）。
