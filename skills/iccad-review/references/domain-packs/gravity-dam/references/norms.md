# 混凝土重力坝工程报告审查 — 规范取用与引用纪律

## 一、取条文的方法（唯一权威定义）

判词要有依据，依据要有条号，条号要能追到原文。取条文用 **`scripts/spec_lookup.py`**，
默认读**本技能自带**的 `references/gd_clauses.json`（SL 319-2018 精编 140 条 + 18 部配套规范块库 13,682 块，合计 **13,822 块**），
零外部依赖、与当前目录无关。

```bash
# 库内有哪些规范、各多少块
python scripts/spec_lookup.py --list-specs

# 查条文（关键词过滤）
python scripts/spec_lookup.py --spec "SL 319" --q <关键词>
# 多部一起查
python scripts/spec_lookup.py --spec "SL 319,GB 50201" --q 防洪标准

# 完全静默（诊断默认已走 stderr，stdout 只留条文正文）
python scripts/spec_lookup.py --spec "SL 319" --q <关键词> --quiet
```

**查条文三条纪律**（不遵守会白跑一轮）

1. **用规范原文的术语，别用同义词。** `--q` 是**字面包含**匹配（已做**去空白 + 忽略大小写**
   容错 —— 库内正文多来自 PDF/OCR，常写成"抗 滑 稳 定"，直接查"抗滑稳定"也能命中）。
2. **条号用纯数字。** `clause` 字段是 `7.4.4` 这种纯号，`--q 表7.4.4` 会 0 命中；
   表块 `clause` 记为表号（如 `表6.4.1-1`），查表要用 `--q 表6.4.1-1`。
3. **优先用词组，别用单字。** 命中数看 stderr 的 `matched: N (of M)`，N 过大就换更窄的词。

> 本版 `spec_lookup.py` 已做**条号优先排序**：条号/表号**精确相等**排最前，其次是前缀命中，
> 最后才是正文提及（此前出现过查 `7.4.4` 把"见 7.4.4 条"的 7.4.5 排到首位的问题，已修）。

**限值表格**走 `gd_tables.md`（原文表格 + 条文库洁净文本双源互校）；
**强制性条文**走 `compulsory-clauses.md`。**三者都不可凭记忆写。**

**重建条文库**：规范库或收录范围变化后跑
`python scripts/build_clauses.py`（依赖本机块库 pkl 与 hydro_reviewer 源码树）。日常审查**不需要**跑它。

### ⚠️ 块库 SL 319 是 2005 版（本域最大的坑）

本机块库（`chunks.pkl`）里的 SL 319 全文是 **2005 版（876 块）**，与现行 **2018 版条号不等价**。
实测四处位移：

| 差异 | 2005 版 | 2018 版 |
|---|---|---|
| 坝顶高程 | 4.2（在"坝体结构"下） | **新增 4.2「坝顶高程及布置」** → 非溢流/溢流/泄水孔整体后移为 **4.3/4.4/4.5** |

| 章号 | 温控 9、监测 10 | **新增第 9 章「加高与加固设计」** → 温控 **10**、监测 **11** |

> **因此本技能不直接用块库建主规范条文**，而走 `references/gd_clauses_src.txt` 原文精编
> （`build_clauses.py` 双数据源：主规范精编 + 配套 18 部块库）。
> 若某条只在本册标 `【05】`，说明 2018 句级原文未核到 —— **只可引到节号，不得补条号**。

## 四、引用纪律（硬规则）

1. **条号必须取自原文。** 每条判定都要能追到"规范号 + 条号 + 原文"。取不到就标"依据待核"。
2. **区分"应/不应"与"宜/不宜"。** 用词层级：**必须/严禁** > **应/不应** > **宜/不宜** > **可**。
   "不应大于 X"是**硬约束**（判不合格）；"宜采用 Y"是**推荐**（只出提示，不判不合格）。
   把"宜"当"应"判 = 误判；把"应"当"宜"放过 = 漏判。
3. **强条单独标注。** 触发 `compulsory-clauses.md` 里的条文 → 写"**违反强制性条文**"，最高级。
4. **两套判据别用混。** 同一指标若两部规范都有（如地基承载力 GB 50007 vs 坝基容许应力 SL 319）
   → 按建筑物性质与所属规范选，**不可互代**；两值都给出时取**较严者**并说明。
5. **版本必须声明。** 引旧版 → 直接出"**引用已废止标准**"问题。注意标准更名/换号（SL→SL/T 前缀）。
   本域高频：SL 319-2005、SL 203、SL 282。
6. **库态只认实测。** 部数与块数用 `--list-specs` 点数，不用文件时间戳判断。
7. **不得据 `level` 字段判强条。** 库内 `level` 是按措辞（应/宜）自动标注的，
   **不等于强条**。强条只认 `compulsory-clauses.md` 的六条清单。

## 五、易踩的坑

1. **把块库 SL 319 当 2018 版用** → 条号全错（4.2/4.3 错位、6.3.2/6.3.3 互换、7.4 前移）。
   已在 `build_clauses.py` 里写死"主规范不走块库"，但**人工引用时仍须自查**。
2. **公式本体在 docx 里是嵌入图片** → 块库只有符号说明，没有公式。附录 A/B/C/E 的公式
   一律以 `gd_tables.md` 固化式为准，或标"公式待核"。
3. **表格 `table_text` 随规范而异** → 有的规范块库带表体、有的只有表号。限值一律以
   `gd_tables.md` 固化值为准，**不要指望 `spec_lookup` 返回表体**。
4. **OCR 空格让关键词查不到关键条** → 已做去空白归一化，但**数字与单位之间**的空格仍可能
   影响（如 "0.07 倍"），查数值优先查中文词组（"拉应力区宽度"）。
5. **`--q` 不是语义检索** → 同义词不通用。"扬压力"查不到"渗透压力"条，两个词都要查。
6. **主规范是否在强条汇编内** → SL 319-2018 在汇编内（6 条），但**汇编页码标注为 32/44/51**，
   即强条集中在第 4、6、7 章；第 8~11 章**无强条**，不要硬凑。
7. **本域最容易写小的数值**：
   - 安全加高（0.3 写成 0.5，级别与工况双维查表易串）；
   - 帷幕深度比（0.3H 写成 0.5H）；
   - 排水孔深（漏掉"高/中坝 ≥10m"这条并列条件）；
   - 有限元拉应力区宽度（漏掉"且小于 0.07B"这个并列条件）。
8. **区间值只判下限会漏**：如帷幕 q "1~3 Lu"，报告给 4 Lu 时高出上限也算不合格
   （上限型），不能因为"≥1"就放过。
