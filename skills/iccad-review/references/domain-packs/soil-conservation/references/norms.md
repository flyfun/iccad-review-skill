# 规范索引与取条文方法

## 一、先取尺子，再下判断

本技能**不硬编码条文**。判定依据一律通过工具从规范库取。

**工具**：`scripts/spec_lookup.py`

**默认数据源 = 技能自带的条文库**（`references/swc_clauses.json`）。
JSON 路径按**脚本所在位置**定位，因此在任何目录下调用都能找到，**不需要本机任何外部路径**。

```bash
# 看自带库里有啥（唯一可靠的口径）
python spec_lookup.py --list-specs

# 取条文（关键词过滤）——默认走自带 JSON，无需任何附加参数
python spec_lookup.py --spec "GB 51018" --q 弃渣场
python spec_lookup.py --spec "GB 50433" --q 取土场
python spec_lookup.py --spec "GB/T 50434" --q 指标值
python spec_lookup.py --spec "GB 51018,SL 575" --q 防洪标准 --limit 30

# 查"自带库之外"的规范：改用本机块库（可选，需 hydro_reviewer 源码树）
python spec_lookup.py --pkl "C:\Users\Administrator\水利审查工具\specs_db\chunks.pkl" --spec "SL 190" --q 允许
```

**自带条文库**：`references/swc_clauses.json` —— **8 部规范（6 部水保规范 + 强条汇编 + 2 部核心国标），共 4,013 块**（其中 **2,830 块带条款号**；清单见第二节）。

**备用数据源（可选）**：`C:\Users\Administrator\水利审查工具\specs_db\chunks.pkl`（全库 41,833 块 / 62 部）。
块库为 pickle 格式，对象类定义在 hydro_reviewer 的 `src/`，读取需源码树在 `sys.path`（脚本会自动加）。
**只有要查自带库之外的规范时才需要它**；默认路径为本机专属、换机器即失效。

**核心国标已入库**：**GB 50433-2018 / GB/T 50434-2018 两部核心标准，已从库外原件（PDF/docx）解析并收入本库**，
可直接 `spec_lookup.py --spec "GB 50433"` / `--spec "GB/T 50434"` 取条文——**含 GB/T 50434 八区防治指标值表 4.0.2-1~8 全表**。
这是相较早期版本的关键升级（此前两部标准"块库未收录"，只能查固化表）。其关键条文与限值另**固化**一份在
`references/swc_tables.md`（与 `calc_swc_targets.py` / `calc_dregs.py` 内联限值一致），**两者互为校验**。

> 三条通道不可混用：**可检索条文** 走 `spec_lookup.py`（现已含 GB 50433 / GB/T 50434）；
> **固化限值表** 走 `swc_tables.md`；**强制性条文** 走 `compulsory-clauses.md`。都不可凭记忆写。

**查条文三条纪律**（2026-10-16 实测；写法不当会让载入量差几十倍，甚至 0 命中）：

| 纪律 | 错例（实测） | 正解 |
|---|---|---|
| **优先词组、少用单字** | `--q 弃渣` → **48 条 / 6,945 字符** | `--q 弃渣场级别` → 5 条 / 1,781 |
| **条号用纯条号** | `--q 5.7.1` 与 `--q 表5.7.1` 实测同值；但**其他规范**带"表"字会 0 命中 | 统一用 `--q 5.7.1` |
| **认准规范编号再查** | 凭印象写编号常查空（如 GB/T 前缀有无"/T"） | 先 `--list-specs` 看准编号，再用该规范原文用词 |

**输出约定**：诊断信息（`loaded` / `matched` / `exported`）一律走 **stderr**，**stdout 只有条文正文** ——
可直接管道或计量载入量；要连诊断也静默，加 `--quiet`。

**子串匹配的局限**：`--q` 是**字面包含**匹配，不是语义检索——命中块里常混入只是"提到该词"的低相关条文，
**取回后须人眼挑出真正对口的那条**，不要整块照抄进审查意见。

**重建条文库**：规范库更新后跑 `python scripts/build_clauses.py`（库内 6 部依赖本机 pkl 与源码树；
库外 2 部核心国标从原始文件解析，路径见脚本 `EXTERNAL` 常量）。

## 五、引用纪律（硬规则，违反即为错误结论）

1. **条款号一律来自 `spec_lookup.py` 输出或已固化的 `swc_tables.md` / `compulsory-clauses.md`**，不凭记忆写。
2. **取到条文原文再判**。写"违反 GB 51018 12.2.2"之前，先跑一次工具把 12.2.2 原文调出来核。
3. **强条不得降格**。强制性条文不满足即写"**违反强制性条文**"，不得写成"不符规范推荐"。
4. **数值型条款必须保真**。防治指标值、弃渣场级别、防洪标准、抗滑安全系数、容许土壤流失量等指标型条款是审查核心。
5. **版本必须声明**。库内 GB 51018 为 2014 版、SL 575 为 2012 版、SL 190 为 2007 版、GB 50433/GB/T 50434 为 2018 版；
   有新版时以现行版为准（**SL/T 277 库内已为 2024 版**）。
6. **不确定就标"待核"**，不编、不凑。
7. **规范原文属内部资料**，本 skill 的固化数据仅供本机审查使用，不外传。

## 六、易踩的坑

1. **概念别混**：**水土流失防治责任范围** ⊆ 项目征占地 + 其他使用与管辖区域；**防治分区**是按地貌/流失类型/工程布局细分。
   "直接影响区"在 GB 50433-2018 已**取消**（不再划入责任范围）。
2. **标准名与号**：`GB 50433` 2008 版名《开发建设项目水土保持技术规范》，2018 版更名《**生产建设项目**水土保持技术标准》。
   汇编 6-2-1 行仍写旧名+新号（GB50433—2018），**以 2018 版为准**。
3. **两部核心标准已入库但需核 OCR**：GB 50433 / GB/T 50434 可直接 `spec_lookup` 取条文；因来自 PDF/docx 解析，
   正文偶有 OCR 噪声（如"取土(石、砂〉场"），**引条号 / 引限值前先与 `swc_tables.md` 互校**。
4. **"六项指标"口径**：水土流失治理度、土壤流失控制比、渣土防护率、表土保护率、林草植被恢复率、林草覆盖率——
   施工期**只核后两项中的渣土防护率与表土保护率**（治理度/控制比/恢复率/覆盖率施工期不作要求）。
5. **风沙区表土保护率不作要求**（占地为耕地/园地时才剥离保护）。
6. **强条别漏判**：GB 50433 的 3.2.3/3.2.5（取土场/弃渣场**选址禁区**）、GB 51018 12.2.2（弃渣场选址）、
   SL 575 4.1.1/4.1.5/4.1.11/4.2.1 是水保报告最高频"踩线"条款。
7. **编制规程 ≠ 技术标准**：GB 50433 附录 B/C 管"方案报告该写什么"，用它判"工程怎么做"会判错。
8. **库态只认实测**。块数与部数用 `--list-specs` 点数，不要用文件时间戳判断。
9. **公式图形化**：部分原文公式为**嵌入图片**（GB 50433 亦如此），条文库只存符号说明文字。
   水土流失量预测公式 `W=Σ F·M·T` 已固化为文字（`swc_tables.md` §四），其余取公式须回原文。
10. **库外原件解析 ≠ 官方电子版**：GB 50433 来自 PDF、GB/T 50434 来自 docx，
   个别字符（数学符号、上下标、表格合并格）可能失真——**凡引到具体数值，务必交叉核对 `swc_tables.md` 或纸质原件**。
