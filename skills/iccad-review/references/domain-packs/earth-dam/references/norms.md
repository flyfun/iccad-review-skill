# 规范索引与取条文方法

## 一、先取尺子，再下判断

本技能**不硬编码条文**。判定依据一律通过工具从规范库取。

**工具**：`scripts/spec_lookup.py`

**默认数据源 = 技能自带的条文库**（`references/dam_clauses.json`）。
JSON 路径按**脚本所在位置**定位，因此在任何目录下调用都能找到，**不需要本机任何外部路径**。

```bash
# 看自带库里有啥（唯一可靠的口径）
python spec_lookup.py --list-specs

# 取条文（关键词过滤）——默认走自带 JSON，无需任何附加参数
python spec_lookup.py --spec "SL 274" --q 坝顶超高
python spec_lookup.py --spec "SL 274,SL 258" --q 安全系数 --limit 30

# 查"自带库之外"的规范：改用本机块库（可选，需 hydro_reviewer 源码树）
python spec_lookup.py --pkl "C:\Users\Administrator\水利审查工具\specs_db\chunks.pkl" --spec "SL 189" --q 坝坡
```

**自带条文库**：`references/dam_clauses.json` —— **19 部 / 13,480 块**，其中 **10,595 块带条款号**（清单见第二节）。

**备用数据源（可选）**：`C:\Users\Administrator\水利审查工具\specs_db\chunks.pkl`（全库 41,833 块 / 62 部）。
块库为 pickle 格式，对象类定义在 hydro_reviewer 的 `src/`，读取需源码树在 `sys.path`（脚本会自动加）。
**只有要查自带库之外的规范时才需要它**；默认路径为本机专属、换机器即失效。
可用 `--pkl` / `--src` 参数覆盖，或设环境变量 `SPECS_DB` / `HYDRO_SRC`。

**限值表（另一条通道）**：规范原文的**参数表**（安全加高、稳定允许系数、压实度、相对密度…）
在条文库中**未被完整保留为结构化表格**。这些限值另从原始 docx 提取，固化在
**`references/dam_tables.md`** —— 判定取限值查这里，与 `calc_dam_crest.py` / `calc_dam_slope.py`
内联限值一致。

> 注意区分：**条文的文字**走 `spec_lookup.py`；**限值表格**走 `dam_tables.md`（docx 提取）。
> 两者都不可凭记忆写。

**查条文三条纪律**（2026-10-16 实测；写法不当会让载入量差几十倍，甚至 0 命中）：

| 纪律 | 错例（实测） | 正解 |
|---|---|---|
| **优先词组、少用单字** | `--q 坝` → **231 条 / 7,374 字符** | `--q 坝顶超高` → 3 条 / 666；`--q 反滤层` → 32 条 / 4,557 |
| **条号用纯条号，别带"表"字** | `--q 表5.2.1` → **0 命中** | `--q 5.2.1` → 1 条（库内 `clause` 字段不含"表"字） |
| **认准规范编号再查** | 凭印象写编号常查空 | 先 `--list-specs` 看准编号，再用该规范原文用词 |

**输出约定**：诊断信息（`loaded` / `matched` / `exported`）一律走 **stderr**，**stdout 只有条文正文** ——
可直接管道或计量载入量；要连诊断也静默，加 `--quiet`。

**子串匹配的局限**：`--q` 是**字面包含**匹配，不是语义检索——命中块里常混入只是"提到该词"的低相关条文，
**取回后须人眼挑出真正对口的那条**，不要整块照抄进审查意见。

**重建条文库**：规范库更新后跑 `python scripts/build_clauses.py`（依赖本机 pkl 与源码树）。

## 五、引用纪律（硬规则，违反即为错误结论）

1. **条款号一律来自 `spec_lookup.py` 输出或已固化的 `dam_tables.md` / `compulsory-clauses.md`**，不凭记忆写。
2. **取到条文原文再判**。写"违反 SL 274 8.3.10"之前，先跑一次工具把 8.3.10 原文调出来核。
3. **强条不得降格**。15 条强制性条文不满足即写"违反强制性条文"，不得写成"不符规范推荐"。
4. **数值型条款必须保真**。安全系数、超高、压实度、相对密度、渗透系数等指标型条款是审查核心。
5. **版本必须声明**。库内 SL 274 为 2001 版；项目适用 2020 版时须回现行版核对。
6. **不确定就标"待核"**，不编、不凑。
7. **规范原文属内部资料**，本 skill 的固化数据仅供本机审查使用，不外传。

## 六、易踩的坑

1. **版本替代**。`SL 203 → GB 51247`（抗震）。报告引旧版且新规范已强制 → 属问题。
2. **SL 274 版本**。库内 2001 版，现行 2020 版，**不可默认等价**。
3. **编号变体**。`SL 274` ≡ `SL/T 274` ≡ `SLT 274`，`/T`、强制↔推荐 归一化后视为同一规范。
4. **编制规程 ≠ 设计规范**。SL/T 618/619 管"报告写什么"，用它判"工程怎么做"会判错。
5. **库态只认实测**。块数与部数用 `--list-specs` 点数，不要用文件时间戳判断。
6. **公式图形化**。SL 274 原文的波浪/稳定计算公式多为**嵌入图片**，条文库只存了符号说明文字。
   取公式须回原始 docx 提图识读，**不能凭"公式编号"猜形式**。
7. **无手册可引**。《水工设计手册》第六卷（土石坝）缺失 —— 审查意见中**不得出现"手册推荐"**。
8. **强条别漏判**。15 条强条集中在坝顶超高（5.3.1/5.3.2/5.3.6/5.5.3）、坝坡稳定（8.3.10/11/12）、
   材料与反滤（4.1.5/4.1.15/4.2.3/4.2.5/5.6.2）、监测（10.0.2/10.0.3/10.0.6）四处。
