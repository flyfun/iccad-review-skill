# 泵站工程报告审查 — 规范取用与引用纪律

## 一、取条文的方法（唯一权威定义）

判词要有依据，依据要有条号，条号要能追到原文。取条文用 **`scripts/spec_lookup.py`**，
默认读**本技能自带**的 `references/ps_clauses.json`（**17 部 / 13,525 块**，零外部依赖、与当前目录无关）。

```bash
# 库内有哪些规范、各多少块
python scripts/spec_lookup.py --list-specs

# 查条文（关键词过滤）
python scripts/spec_lookup.py --spec "GB 50265" --q 特征扬程
# 多部一起查
python scripts/spec_lookup.py --spec "GB 50265,GB 50201" --q 防洪标准
# 纯条号查（不带"表""第""条"）
python scripts/spec_lookup.py --spec "GB 50265" --q 4.3.3

# 完全静默（诊断默认已走 stderr，stdout 只留条文正文）
python scripts/spec_lookup.py --spec "GB 50265" --q 淹没深度 --quiet
```

**查条文三条纪律**（不遵守会白跑一轮）

1. **用规范原文的术语，别用同义词。** `--q` 是**字面包含**匹配（已做**去空白 + 忽略大小写**容错 ——
   库内正文多来自 PDF/OCR，常把词拆字加空格，如"特 征 水 位"，直接查"特征水位"也能命中）。
2. **别带"表/第/条"字查条号。** 库内 `clause` 字段是 `7.1.3` 这种**纯数字**，`--q 第7.1.3条` 会 0 命中。
3. **优先用词组，别用单字。** 命中数看 stderr 的 `matched: N (of M)`，N 过大就换更窄的词。

**限值表格**走 `ps_tables.md`（原文 docx 网格重建 + 条文库洁净文本双源互校）；
**强制性条文**走 `compulsory-clauses.md`。**三者都不可凭记忆写。**

**重建条文库**：规范库或收录范围变化后跑
`python scripts/build_clauses.py`（依赖本机块库 pkl 与 hydro_reviewer 源码树）。日常审查**不需要**跑它。

## 四、引用纪律（硬规则）

1. **条号必须取自原文。** 每条判定都要能追到"规范号 + 条号 + 原文"。取不到就标"依据待核"。
2. **区分"应/不应"与"宜/不宜"。** 用词层级：**必须/严禁** > **应/不应** > **宜/不宜** > **可**。
   "不应低于 X"是**硬约束**；"宜采用 Y"是**推荐**。把"宜"当"应"判 = 误判。
   **注意本域特殊**：4.3.3 "最高扬程**宜**按…"、4.3.4 同 → 属**推荐做法**，报告采用其他口径且**论证充分**时不判错，只提示。
3. **强条单独标注。** 触发 `compulsory-clauses.md` 里的条文 → 写"**违反强制性条文**"，最高级。
4. **两套判据别用混。** 同一指标若两部规范都有（如特征扬程 GB 50265 §4.3 与 GB 50288 5.4.10）→
   按建筑物性质与所属规范选，**不可互代**；但两者口径一致时互为佐证。
5. **版本必须声明。** 引旧版 → 直接出"**引用已废止标准**"问题。
   本域高发：**GB 50265-2010《泵站设计规范》**（已废止，现行 **GB 50265-2022《泵站设计标准》**，
   名称"规范→标准"也变了）、**GB/T 50510-2009**（已废止）。
6. **库态只认实测。** 部数与块数用 `--list-specs` 点数，不用文件时间戳判断。

## 五、易踩的坑（本域实测）

1. **强条汇编引的是 2010 版条号**：汇编里写 **GB 50265-2010 的 6.1.3 / 6.3.5 / 6.3.7**，
   现行 2022 版**同一批强条已后移为 7.1.3 / 7.3.5 / 7.3.8**。**引条号写 2022 版**，否则与现行标准对不上。
2. **主规范的分章正文会被拆块**：`4.2.1` 的第 1 款与第 2~6 款可能落在**两块**（续块 clause 字段为空）。
   查一条款查不全时，用关键词（如"灌溉泵站进水池水位"）再捞一次。
3. **块库把表格内嵌在 `text` 字段**（`【表格 - N行×M列】` 开头的 markdown），**不是** `table_text`；
   数值限值一律以 `ps_tables.md` 固化值为准。
4. **OCR 空格**：`--q` 已做去空白容错，但**同义词不通用**（`--q 站上水位` 不会命中只写"出水池水位"的条 —— 那是术语边界，不是 bug）。
5. **附录 A 是参数表不是公式表**：GB 50265 附录 A 给 f / φ₀ / C₀ / f' / C'（**非图片**，已固化），
   而**稳定计算公式本体**（7.3.4 各式的 ΣM/ΣP 展开）在库内是文字描述，**复算须自建力系**，脚本只做"限值比对"。
6. **"最高扬程宜…"是推荐**：4.3.3/4.3.4 用"宜"，报告若采用"遭遇概率小、经论证降低"的取值，
   只要**论证在**就不判硬错，只出提示。
7. **安全加高"取大值"**：设计运用与校核运用要**各算一遍取大**，不是取设计那一栏了事。
8. **立式泵基准面 ≠ 底板**：淹没深度 0.5 m 量的是**基准面**（叶轮中心/导叶进口），别拿底板高程套。

## 六、与同族技能的关系

| 维度 | 邻域技能 | 本技能 |
|---|---|---|
| 对象 | 河道整治/堤防/护岸/疏浚报告 | **泵站**（供水/灌溉/排水/灌排结合）报告 |
| 主规范 | GB 50707 / GB 50286 / SL/T 386 | **GB 50265** |
| 关注点 | 行洪能力、河道演变、护岸稳定 | **特征水位与特征扬程、安装高程、泵房稳定、机电选型** |
| 重叠条款 | GB 50286（穿堤）、SL 265（防渗排水）、SL 252（级别） | 同一批条款时**判定口径须逐值对齐** |
| 报告名 | 河道整治工程初设/施工图 | 泵站工程初设/可研/**安全鉴定**/**更新改造** |

- **防洪影响**另属 `flood-impact-report-review`；**水闸**属 `sluice-report-review`；**河道/堤防**属 `river-channel-report-review`。
- 泵站**穿堤**时与河道/堤防技能**同看 GB 50286**，但主判据仍是泵站自身的级别与防洪标准。
