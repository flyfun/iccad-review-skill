# 规范索引与取条文方法

## 一、先取尺子，再下判断

本技能**不硬编码条文**。判定依据一律通过工具从规范库取。

**工具**：`scripts/spec_lookup.py`

**默认数据源 = 技能自带的条文库**（`references/rc_clauses.json`）。
JSON 路径按**脚本所在位置**定位，因此在任何目录下调用都能找到，**不需要本机任何外部路径**。

```bash
# 看自带库里有啥（唯一可靠的口径）
python spec_lookup.py --list-specs

# 取条文（关键词过滤）——默认走自带 JSON，无需任何附加参数
python spec_lookup.py --spec "GB 50286" --q 堤防工程的级别
python spec_lookup.py --spec "GB 50707" --q 治导线
python spec_lookup.py --spec "SL 252" --q 工程等别
python spec_lookup.py --spec "GB 50286,GB 50707" --q 安全系数 --limit 30

# 查"自带库之外"的规范：改用本机块库（可选，需 hydro_reviewer 源码树）
python spec_lookup.py --pkl "C:\Users\Administrator\水利审查工具\specs_db\chunks.pkl" --spec "SL 274" --q 坝顶
```

**自带条文库**：`references/rc_clauses.json` —— **15 部规范（河道/堤防主规范 + 等级/防洪/疏浚/治涝 + 配套 + 强条汇编），共 5,808 块**（其中 **4,199 块带条款号**；清单见第二节）。

**备用数据源（可选）**：`C:\Users\Administrator\水利审查工具\specs_db\chunks.pkl`（全库 41,833 块 / 62 部）。
块库为 pickle 格式，对象类定义在 hydro_reviewer 的 `src/`，读取需源码树在 `sys.path`（脚本会自动加）。
**只有要查自带库之外的规范时才需要它**；默认路径为本机专属、换机器即失效。

> 三条通道不可混用：**可检索条文** 走 `spec_lookup.py`；**固化限值表** 走 `rc_tables.md`；
> **强制性条文** 走 `compulsory-clauses.md`。都不可凭记忆写。

**查条文三条纪律**（2026-10-16 压测实测；写法不当会让载入量差 **85 倍**，甚至 0 命中）：

| 纪律 | 错例（实测） | 正解 |
|---|---|---|
| **用该规范自己的术语** | `--q 坡式护岸` 查 GB 50707 → **0 命中** | "坡式护岸"是 GB 50286 §8.2 的词；查 GB 50707 用"防护工程""治导线" |
| **条号别带"表"字** | `--q 表7.2.4` → **0 命中** | `--q 7.2.4`（库内 `clause` 字段不含"表"字） |
| **优先词组、少用单字** | `--q 防护` → **5,993 字符 / 21 条**（大量低相关块） | `--q 稳定安全系数` → 1,180 / 4 条；`--q 填筑标准` → 1,402 |

**输出约定**：诊断信息（`loaded` / `matched` / `exported`）一律走 **stderr**，**stdout 只有条文正文** —— 可直接管道或计量载入量；要连诊断也静默，加 `--quiet`。

**子串匹配的局限**：`--q` 是**字面包含**匹配，不是语义检索。查 `压实度` 会连带返回 7.3.1 堤顶高程、7.3.4 沉降量
（正文提到"压实度"）——**取回后仍须人眼挑出真正对口的那条**，不要整块照抄进审查意见。

**重建条文库**：规范库更新后跑 `python scripts/build_clauses.py`（依赖本机 pkl 与源码树，路径见脚本 `CONFIG`）。

## 四、引用纪律（硬规则，违反即为错误结论）

1. **条款号一律来自 `spec_lookup.py` 输出或已固化的 `rc_tables.md` / `compulsory-clauses.md`**，不凭记忆写。
2. **取到条文原文再判**。写"违反 GB 50286 7.2.4"之前，先跑一次工具把 7.2.4 原文调出来核。
3. **强条不得降格**。强制性条文（GB 50286 7.2.4/7.2.5/10.1.3、GB 50707 4.1.3、SL 252 多条）不满足即写"**违反强制性条文**"，不得写成"不符规范推荐"。
4. **数值型条款必须保真**。堤防级别、安全加高、稳定安全系数、防洪标准、超深超宽等指标型条款是审查核心。
5. **版本必须声明**。库内 GB 50286 为 2013 版、GB 50707 为 2011 版、SL 252 为 2017 版、GB 50201 为 2014 版、SL 17 为 2014 版。
   ⚠ **SL/T 386 为 2025 版，替代 SL 386-2007 与 SL 379-2007**——报告引旧版编号/旧系数时，**先出"引用已废止标准"的版本问题**，再核数值。有新版时以**现行版**为准。
6. **不确定就标"待核"**，不编、不凑。
7. **规范原文属内部资料**，本 skill 的固化数据仅供本机审查使用，不外传。

## 五、易踩的坑

1. **两道"级别"别混**：**工程等别**（SL 252 表3.0.1，按规模/效益，I~Ⅴ）→ **建筑物级别**（1~5 级）；
   **堤防级别**（SL 252 表4.4.1 / GB 50286 表3.1.3）是"永久性水工建筑物级别"的一种，**直接由保护对象防洪标准定**。
   同一工程里"堤防级别"与"河道整治建筑物级别"是两套口径，别串。
2. **防洪标准入口别混**：**城市/乡村/工矿**按 GB 50201 的"防护等级"（按人口/耕地/重要性）；**水利工程**按 SL 252（按规模/效益）。同一防洪标准可能对应不同入口。
3. **安全加高**：**允许越浪**取值明显小于不允许越浪；且允许越浪须**另验越浪量并做防护**（不能只取个小值了事）。
4. **非常运用条件的定义**（GB 50286 9.2.2）：非常运用 I = **施工期**；非常运用 Ⅱ = **多年平均水位遭遇地震**。别把水位的其他组合当成"非常运用"。
5. **软弱地基**抗滑可降（3.2.4）——但必须"**经论证并报行业主管部门批准**"，报告不能自行降低而不说明。
6. **GB 50707 是"整治"不是"堤防"主规范**：河道整治工程的**堤防设计**部分仍以 GB 50286 为准（GB 50707 8.2.5 亦如此指向）。
7. **治导线 ≠ 河道中心线**：治导线是规划拟订的、控制河势的平面轮廓线；有堤河段以**堤线**作为洪水治导线。
8. **生态护坡不是"不做硬防护"**：SL/T 879 要求在**保证安全**前提下采用生态型式，稳定性分析不能省。
9. **公式图形化**：部分原文公式为**嵌入图片**，条文库只存符号说明文字。
   已固化为文字的：堤顶超高 `Y=R+A`、波浪爬高 `R=KΔ·Kv·Kp·R0·H`、Hudson 护面块体 `W=γs·H³/[K_D·(γs/γw−1)³·cotα]`（见 `rc_tables.md`）。其余取公式须回原文。
10. **库态只认实测**。块数与部数用 `--list-specs` 点数，不要用文件时间戳判断。
11. **SL/T 386 别引旧版**：现行 **SL/T 386-2025** 已**替代 SL 386-2007 + SL 379-2007**，章节结构、条款号、安全系数均不同（2025 版把"边坡"与"挡土墙"两本合为一本）。报告按旧版写的，先提版本问题。
12. **SL/T 386 条文说明里的表**（允许渗透坡降、挡墙墙顶安全加高下限值、经验 f 值）是**说明性**材料，引用须注"据条文说明"，不能写成"违反 SL/T 386 X.X 条"。
13. **护岸挡墙稳定判据有两套，按建筑物性质与所属规范选**：防洪墙（GB 50286 表 3.2.5 / 3.2.6 / 3.2.7）与水工挡土墙（SL/T 386 表 3.4.5~3.4.12）各有一套抗滑/抗倾覆/应力比表。
   **土基抗滑两者取值相同**（正常 1.35/1.30/1.25/1.20），但**岩基抗滑不同**：GB 50286 正常 1.15/1.10/1.08/1.05 vs SL/T 386 抗剪公式 1.10/1.08/1.08/1.05（后者另设**抗剪断公式 3.00/2.50/2.30**）。不可互代。
