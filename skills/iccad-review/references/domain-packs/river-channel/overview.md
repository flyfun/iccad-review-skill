# 河道工程报告审查

## 这个 Skill 是什么

**审查编排层**，不是设计知识卡。回答：拿到一份河道工程报告，**按什么顺序查、查哪些点、
每条怎么判、依据谁、怎么输出**。条款号、限值一律从条文库 / 固化表核对，**不硬编码**。
库内**无河道/堤防设计领域技能可路由** → 判据全落在规范库 + 固化限值表 + 复算脚本上。

## 何时用 / 不适用

- **用**：有一份河道工程报告（河道整治 / 中小河流治理 / 堤防 / 护岸 / 清淤疏浚），
  可从规划符合性、级别标准、水力、断面、稳定、护岸、疏浚出发现。
- **不用**：防洪评价 / 洪水影响评价、水土保持方案、土石坝、水闸、纯设计问题、纯条文查询。

## 审查总流程

```
报告文本 (docx/pdf)
 ├─[0]   前置判定 ── 报告类型 / 工程类型 / 河流特性 / 等别级别 / 防洪标准 / 规划依据
 ├─[0.5] 取判据 ── spec_lookup 调条文 + 固化限值表 + calc_*.py 复算
 ├─[1]   分块审查（12 块）── 查什么 → 判定标准 → 依据
 ├─[2]   跨专业一致性 ── 防洪标准↔级别↔断面↔稳定↔护岸↔演变↔投资 数值自洽
 └─[3]   结构化发现 ── 位置 / 问题 / 依据 / 严重度 / 建议
```

**每一步该翻哪一册，见该步末尾的 ▶ 载入。**

---

## 第 0 步：前置判定

**先定这六样，再翻正文。**

| 判定项 | 常见取值 | 对审查的影响 |
|---|---|---|
| **报告类型** | 可研 / 初步设计 / 施工图 / 安全评价 | 决定深度要求与章节完整性 |
| **工程类型** | 河道整治 / 堤防 / 护岸 / 清淤疏浚 / 综合治理 | 决定主用哪部规范 |
| **河流特性** | 顺直 / 弯曲 / 分汊 / 游荡河段；山区 / 平原 | 决定整治原则与断面型式 |
| **工程等别/建筑物级别** | I~Ⅴ 等；1~5 级（SL 252） | **级别定错则断面/加高/稳定取值全错** |
| **防洪标准** | 城市/乡村/工矿 按 GB 50201；水利工程按 SL 252 | 直接决定堤防级别 |
| **规划依据** | 防洪/排涝/航运/岸线利用 规划 | ★强条 GB 50707 4.1.3 要求"符合经审批的规划" |

> 判不出这六样 → 报告基本资料有缺项，本身就是一条 ○ 级发现。

## 第 0.5 步：取判据（别跳过）

**报告是 docx → 先用 `scripts/extract_docx_tables.py <报告> --keyword <词>` 把表格还原成网格**
（判据多藏在堤防断面表 / 工程量表 / 疏浚断面表 / 稳定计算成果表里，顺序拼字会错行）。

三个来源，**不可混用**：

| 来源 | 怎么取 | 怎么写进意见 |
|---|---|---|
| **规范条文** | `python scripts/spec_lookup.py --spec "GB 50286" --q 关键词` | 引条款号（如"违反 GB 50286 表 3.2.1"） |
| **固化限值表** | `rc_tables.md`（级别/加高/稳定/防护/疏浚）+ `rc_works_tables.md`（章节与构造） | 引条款号 + 表号 |
| **强制性条文** | `compulsory-clauses.md`（GB 50707 4.1.3、GB 50286 7.2.4/7.2.5/10.1.3、SL 252 多条…） | 写"**违反强制性条文**"，最高严重级 |

> **查条文三条纪律**（实测：措辞不当会让载入量差 85 倍，甚至 0 命中；详见 `norms.md` §一）：
> ① **用该规范自己的术语**——"坡式护岸"是 GB 50286 的词，拿去查 GB 50707 是 0 命中；
> ② **别带"表"字**——查条号写 `表7.2.4` 查不到，库内的条号字段是 `7.2.4`；
> ③ **优先词组、少用单字**——`防护` 会带回 5,993 字符，`稳定安全系数` 只要 1,180。

> 取不到条文的判定项 → 标"依据待核"，只出疑点不出结论。

**能算的不要只靠看** —— 凡报告给出数值结论，用复算脚本自己过一遍：

| 脚本 | 覆盖 |
|---|---|
| `calc_levee_crest.py` | **堤顶高程 = 设计水位 + 波浪爬高 R + 安全加高 A**（GB 50286 7.3 / 表 3.2.1） |
| `calc_channel_capacity.py` | **河道过流能力（曼宁均匀流）**（矩形/梯形/复式；正算/反算水深） |
| `calc_revetment.py` | **护岸/防洪墙稳定安全系数校核**（表 3.2.3/3.2.5/3.2.6/3.2.7、GB 50707 表 8.2.5）+ 护面块体 |
| `calc_dredge.py` | **清淤疏浚断面/工程量/超深超宽/坡比**（SL 17） |

> ▶ **载入**：`references/norms.md` §一（取条文方法、数据源、脚本用法与限制）。

## 第 1 步：分块审查（12 块）

| # | 审查块 | 重点查什么 | 依据 |
|---|---|---|---|
| 1 | **编制依据、任务与规模** | 依据现行性、阶段、工程任务/规模、**与规划一致** | GB 50707 4.1.3★ |
| 2 | **基本资料** | 水文系列、设计洪水、地质剖面、**河床演变**、地形断面 | SL 44 / GB 50707 6 |
| 3 | **河道整治规划与治导线** | 整治原则（按河型）、**治导线**（有堤河段以堤线为洪水治导线）、标准协调 | GB 50707 4.2/7 |
| 4 | **等别、级别与防洪标准** | **工程等别（表3.0.1）→ 堤防级别（表4.4.1）**、防洪标准入口 | SL 252★ / GB 50201 |
| 5 | **水力计算与行洪能力** | 水面线、各频率过流能力 → `calc_channel_capacity.py` | SL 104 / GB 50707 5 |
| 6 | **堤线布置与堤型** | 堤线平顺（不折急弯）、留有滩地、堤距统筹、堤型选择 | GB 50286 §5 |
| 7 | **堤基处理** | 清水/透水/多层/岩石堤基处理、**渗流控制**、垂直防渗 | GB 50286 §6 |
| 8 | **堤身设计** | **堤顶高程/安全加高、堤顶宽度、填筑压实度★**、堤坡戗台、护坡、防渗排水 | GB 50286 §7 |
| 9 | **护岸与防护工程** | 防护型式（坡式/墙式）、结构材料、**长度、稳定安全系数**、生态护坡 | GB 50286 §8 / GB 50707 8.2 |
| 10 | **稳定与渗流计算** | 边坡抗滑/抗滑/承载力/**抗倾覆**、三工况（含地震） | GB 50286 §9 |
| 11 | **清淤疏浚** | 断面/坡比、**超深超宽**、弃土去向、施工安全环保★ | SL 17 |
| 12 | **管理、监测与生态护坡** | 管理范围（护堤地）、安全监测、生态护坡 | GB 50286 §12/13 / SL/T 879 |

## 第 2 步：跨专业一致性（最容易被漏的一层）

单块各自正确 ≠ 报告正确。共 **8 对交叉校验**（保护对象↔标准↔级别、设计洪水↔水面线↔堤顶高程、
治导线↔堤线↔护岸、级别↔加高↔宽度↔稳定、堤基↔处理↔渗流↔防渗排水、断面↔坡率↔安全系数、
演变↔冲刷↔埋深、内部数值一致）。
> ▶ **载入**：`references/checklist.md` §第 2 步。自洽性优先用复算脚本验算，不靠眼看。

## 引用纪律（硬规则）

**下判断前先读** `references/norms.md` §四（引用纪律 7 条）+ §五（易踩的坑）——唯一权威定义，本入口不重复。

## 边界

- 无河道/堤防设计领域技能可路由——只给**条文级判据 + 固化限值表 + 复算**（详见 `limits.md`）。
- 防洪评价 / 洪水影响评价、水土保持、土石坝、水闸不在范围；产出为**审查发现**非审批结论，责任在人。

> ▶ **载入**：`references/limits.md`（边界与已知局限）。
