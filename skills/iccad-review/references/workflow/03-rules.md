# 审查规则编制与验证

依据是「条文说了什么」，规则是「怎么在报告里判它」。中间这一步不写清楚，检查就会变成凭感觉。

## 四种规则

| criterion.kind | 用于 | 必须写清 |
|---|---|---|
| `numeric` | 压实度、渗透系数、超高、安全系数、单宽流量、投资指标 | 对象、单位、算子、阈值、前提条件、等别分档 |
| `consistency` | 正文与附表、正文与图纸目录、计算书与结论 | 两侧定位方式、允许差异、判矛盾的边界 |
| `completeness` | 必备篇章/附表/附图、责任表与签章、计算书对应项 | 应有清单、覆盖判定口径 |
| `qualitative` | 「应论证」「应说明理由」「应结合…确定」 | 可观察判据、必须保留的证据、什么情况算未论证 |

## 编制步骤

1. 从 [规范依据核验](../workflow/02-standards.md) 取已核验依据卡，确认适用条件（等别/类型/阶段/地区）。
2. 写对象范围 `object_scope`：**限定越松，误报越多**。「全部填筑体」与「培厚段填筑」是两条规则。
3. 定判据。数值型给出 `operator`、`threshold`、`unit`；一致性型给出两侧定位与容差。
4. 准备正反样本：一条能触发、一条不应触发，写入 `test_ref`。**没有反样本的规则等于没验证**。
5. 人工复核后置 `status=verified`，写 `verified_by`、`verified_at`、`verification_ref`。
6. `status=draft` 的规则**不得**用于 `evaluated` 检查项；未知的阈值、单位、条文位置一律填 null，等依据到手再补。

## 数值规则的三条纪律

1. **不猜阈值**。条文没给具体数、或给的数有条件（「经论证可适当降低」）时，规则保持 draft 或改为 `qualitative`。
2. **单位必须在脚本 `UNITS` 表内**。表外单位（复合单位、含修约规则、工程容差）交专项工具，不擅自换算成近似值。
3. **等别敏感项必须分档**。土石坝、堤防、水闸的阈值随工程等别与建筑物级别变化；一条规则覆盖全部等别是常见错误来源。

## 规则可执行性自检

- [ ] 判据能否只靠报告文本/表格得出？需要图元、几何或外部计算才能判的，规则应标注能力前提，运行时记 `unsupported`。
- [ ] 反样本确实不触发？
- [ ] 阈值来源能追到条文号？
- [ ] 结论措辞是否只描述事实（「控制值为 96%，低于 98%」）而不是「设计不合格」？
- [ ] 是否会被同类表述误触发（换了说法的同义表述）？

## 输出与交接

写入 `rules`：`id`、`version`、`discipline`、`basis_ids`、`applicability`、`status`、`criterion`、验证记录、`test_ref`。

规则库按专业分文件维护，改规则后必须回归：用既有样本重跑，确认召回没有退化、误报没有增加。改完不回归，问题会在下一份报告里以另一种形式出现。
