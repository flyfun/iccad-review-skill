# 与确定性引擎的桥接

本页只讲**纪律**。引擎能干什么、字段怎么映射、章节对应哪个包，见
[引擎能力映射](engine-assets.md)；三套状态口径怎么换算，见 [口径对照](status-mapping.md)。

引擎（`SLReview_Py`）解决的是「规则能算的算出来」，本套件解决的是「范围、依据、证据、闭环、审签条件」。
两者都不出「工程通过审查」的结论。

| | 引擎 | 本套件 |
|---|---|---|
| 定位 | 规则可判定项的快速筛查 | 审查范围与证据的组织、留痕与审签条件 |
| 输出 | 命中清单 / 覆盖度 / 逐项判词 | 计划项、依据卡、疑点台账、闭环记录 |
| 判定权 | 无 | 无（判权在人工） |
| 覆盖 | 规则可判定项 | 规则 + 推理 + 资料完整性 |

## 五条硬规则

1. **引擎结论不等于疑点定稿**。导入项一律 `origin=engine`、`confidence<=medium`、`review.status=pending`，
   复核后才改。
2. **不自动产生 P1**。引擎可以标「重大」，P1 是人工的注意力分流（防洪安全、结构安全、强条、关键结论链），
   导入时最高 P2，严重度写进 `observation`。
3. **无引文不补造**。判词说「不符合」但引文未通过校验 → 记 `insufficient_input`；
   清单判「缺失」→ 证据只能写**检索范围**，`locator` 固定 `全文（未命中）`，不得伪装成原文。
4. **依据卡一律待核验**。引擎的规范号 + 条号落成 `authority=unknown`、`status=unknown` 的依据卡，
   经 [规范依据核验](workflow/02-standards.md) 核到官方来源后才升 `effective`。
5. **规则结论与模型结论分开记**。引擎判词的 `method`（`toc-match`/`param-audit`/`conclusion-audit`/`section-audit`）
   保留在 `engine_ref` 里，报告中也必须标出判定方式。

## 不导入的部分

- 引擎的「经验要点清单」：提示性材料，不构成检查项，由各专业 Skill 按需查阅。
- 引擎的领域与等别判定：仅作参考，不写入 `project.grade`；模块以 [双维路由与计划检查项](workflow/04-route.md) 为准。
- 引擎生成的批注版与意见书：口径不同，本套件用 `render_report.py` 与 [意见书与审签准备](workflow/06-report.md) 生成。
- 引擎的 `*_clauses.json`（标准全文）：授权边界与体积原因不入库，本机自用另行同步。
