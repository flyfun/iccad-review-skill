# 跨篇章接口与图文附表一致性审查

单篇都对，合起来错——这是综合审查最容易漏掉的一类问题，也是审签时最容易被追问的一类。

## 接口矩阵

按「谁给谁条件」核对，每一格都要能指出具体数值与位置。

| 上游 → 下游 | 传递什么 | 常见断裂 |
|---|---|---|
| 水文 → 规模 | 特征水位、来水、沙量 | 规模按另一组水位定 |
| 规模 → 建筑物 | 设计流量、水位、孔口尺寸 | 建筑物按单孔流量设计 |
| 地质 → 建筑物/计算 | c、φ、承载力、渗透系数 | 建议值与采用值不同 |
| 水文 → 施工 | 分期洪水、导流流量 | 导流标准与分期洪水不匹配 |
| 建筑物 → 概算 | 工程量、材料、设备 | 概算量取自上一版 |
| 施工 → 概算 | 临时工程、进度、措施费 | 施组变了概算没变 |
| 各专项 → 概算 | 水保、环保、移民投资 | 重复计列或漏计 |

## 一致性核对清单

**编号类**
- [ ] 章节编号连续，交叉引用（「见 5.2.3」）指向存在的内容
- [ ] 表号、图号连续且与目录、图纸目录一致
- [ ] 附录/附件编号与正文引用一致

**数量类**
- [ ] 同一工程量在正文、工程量表、概算三处一致
- [ ] 建筑物座数、孔数、长度在总布置、结构、概算三处一致
- [ ] 征地面积与移民、水保、概算口径一致

**单位与量纲**
- [ ] 万 m³ / m³、L/s / m³/s、cm/s / m/d 全文统一
- [ ] 表中单位标注在表头而非单元格内

**结论类**
- [ ] 各章小结与总结论不矛盾
- [ ] 摘要/结论中的数字与正文一致
- [ ] 「满足要求」的表述有对应计算支撑

**体例类**
- [ ] 术语与工程名称全文一致（同一建筑物不出现三个叫法）
- [ ] 规范名称与编号写法统一
- [ ] 数字与单位间空格、百分号用法统一

## 三项全量扫描不可省

必查清单管「算没算、评没评」，**不管**前后不一致、该引未引、文字体例错误。这三类只能靠逐段扫：

1. **前后不一致**：同一事实在不同位置的不同表述。
2. **该引未引**：结论无出处、数据无来源、措施无依据。
3. **文字与体例**：错别字、标点、编号跳号、图表标题缺失。

只跑必查清单就出报告，条数看着不少，但会成批漏掉细颗粒问题，且漏在哪里无从察觉。

## 输出与交接

矛盾类问题记 `kind=document_conflict`，**必须给两侧不同来源与定位**（如「正文 5.2.2」与「图纸目录 SJ-02」）。

- 一个问题只记一次，主责归最实质的专业，其余专业引用该条。
- 单纯体例问题记 `P3`，不升格为技术问题；但**不影响**其必须记录。
- 换版复查时，接口矩阵是核对清单：任何一格的上游变了，下游都要重查。
